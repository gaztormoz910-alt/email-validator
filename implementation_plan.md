# Поддержка загрузки огромных файлов (Massive Files Mode)

Для того чтобы загружать файлы на десятки гигабайт без лагов и зависаний, нам нужно полностью переработать то, как программа работает с памятью (ОЗУ). Сейчас она пытается загрузить весь файл сразу в оперативную память и отобразить его в текстовом поле, что приводит к крашу при больших объемах.

## User Review Required

> [!WARNING]  
> Важное изменение: Для огромных файлов мы отключим предварительный просмотр текста в поле интерфейса (внутри текстового окна). Вместо этого программа просто напишет "Загружен огромный файл: [Имя файла]" и будет считывать его построчно (Lazy Loading) уже непосредственно во время самой валидации. Это позволит избежать "подвисаний" окна программы.

## Proposed Changes

### `ui/gui.py`
Изменение логики загрузки файлов в интерфейсе.
- Вместо хранения гигантского словаря `self.raw_emails` мы будем хранить массив путей к файлам `self.input_files`.
- В функции `load_file()` будет добавлена проверка размера файла. Если файл огромный (например, > 20 МБ), он **не будет** парситься сразу и добавляться в текстовое поле. Программа просто сохранит путь к нему.
- При нажатии на кнопку "Запуск" программа передаст в Pipeline пути к файлам, а не словарь в ОЗУ.

### `core/pipeline.py`
Переработка пайплайна (ядра) валидатора под построчное потоковое чтение (Streaming).
- Метод `run_pipeline` будет принимать список путей к файлам вместо словаря.
- Чтение файлов будет происходить "на лету" (on-the-fly) с помощью генераторов (yield), порциями (например, по 1000 строк). Каждая порция будет отправляться в пулы потоков на валидацию, а затем удаляться из ОЗУ.
- Это гарантирует, что потребление ОЗУ будет стабильно низким (в пределах 100-300 МБ) даже при файлах размером в 100 ГБ.

### `core/cleaner.py`
Адаптация фильтрации от мусора под потоковое чтение.
- Перепишем функцию `process_batch` так, чтобы она могла принимать генераторы и возвращать очищенные email-ы "на лету", а не перемалывать весь словарь разом.

## Verification Plan
1. Сгенерируем тестовый текстовый файл размером около 1 ГБ.
2. Попробуем загрузить его в софт. Интерфейс не должен зависнуть ни на миллисекунду.
3. Запустим валидацию — потребление ОЗУ в Диспетчере задач должно оставаться минимальным и стабильным.
