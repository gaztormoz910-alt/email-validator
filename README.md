# Валидатор email

Проверяет, существует ли почтовый ящик, и обогащает базу (имя, пол, страна,
провайдер). Работает через прокси, не выдаёт вердикт, которого не доказал, и
показывает, насколько каждому вердикту можно верить.

Всё, что здесь написано, сверяется тестом `tests/test_audit5.py::test_readme_*`:
если команда или зависимость разойдётся с кодом, набор упадёт.

## Установка

```
pip install -r requirements.txt
```

Для разработки и прогона тестов дополнительно:

```
pip install -r requirements-dev.txt
```

Необязательное: `spacy` нужен только при включённом переключателе «AI фильтр»,
модель к нему ставится отдельно — `python -m spacy download en_core_web_sm`.

## Запуск

| Команда | Что делает |
|---|---|
| `python main.py` | окно на веб-стеке (pywebview + WebView2) — основной интерфейс |
| `python main.py --classic` | прежнее окно на CustomTkinter, запасное |
| `python cli.py validate --emails base.txt --proxies socks5.txt -o out.csv` | проверка без окна |
| `python -m api.server` | локальный HTTP-API на 127.0.0.1 |

Командная строка умеет и операции с базами без проверки:

```
python cli.py subtract base.txt unsubscribed.txt -o clean.txt
python cli.py merge a.txt b.txt -o all.txt
python cli.py intersect a.txt b.txt -o both.txt
```

## Про прокси

Валидатору нужен **исходящий порт 25**. Порты 587 и 465 — для отправки через
релей, к проверке существования ящика отношения не имеют. Прокси проверяются
соединением именно на 25-й порт с чтением баннера `220`.

Отдельным провайдерам нужно больше:

| Что нужно | Кого открывает |
|---|---|
| просто рабочий прокси | Gmail, Yandex, Proton, большинство корпоративных |
| чистая репутация IP | Outlook, Hotmail, Live, iCloud, GMX |
| PTR-запись (FCrDNS) | Yahoo, AOL, Verizon |

Резидентные и мобильные прокси для проверки не годятся: у них нет PTR и они
лежат в Spamhaus PBL по определению.

**Без прокси проверка по SMTP не идёт вовсе.** Это не ограничение, а защита:
прямое соединение раскрыло бы домашний IP почтовикам. Если прокси заданы, но
все выбыли, программа честно говорит об этом и не идёт напрямую.

## Что означают вердикты

| Статус | Что доказано |
|---|---|
| **Valid** | сервер принял адрес; при контрольной пробе он же отверг выдуманный |
| **Invalid/Bounce** | сервер назвал получателя несуществующим, либо адресовать некуда (нет MX, сломан синтаксис) |
| **Risky** | ответа про ящик не было: отказ по репутации нашего IP, нарушено правило провайдера, серверы разошлись во мнениях |
| **Unknown** | проверка не состоялась (таймаут, прокси, лимит) либо домен принимает ЛЮБОЙ адрес (catch-all) |
| **Role-based** | адрес служебный (info@, support@) — существовать может, писать не стоит |
| **Trap/Disposable** | одноразовый домен или ловушка антиспам-вендора |
| **Unverified** | проверка по SMTP была выключена — про ящик не известно ничего |

Рядом с вердиктом стоит **уверенность 0-100** и её основание — отдельно от
скора живости. Скор отвечает «похоже ли, что за адресом живой человек»;
уверенность — «насколько твёрдо доказано то, что написано в статусе».
Подтверждённый контрольной пробой ящик и «домен принимает что угодно» — это
одно слово «Годен» и совершенно разные основания. Обе величины есть и в
таблице, и в выгрузке (колонки `Confidence` и `ConfidenceBasis`).

**Чего не может никто.** Дата последнего входа в ящик, история отскоков и
списки спам-ловушек не отдаются провайдерами никому — это потолок
SMTP-валидации как таковой, а не недоделка. Поэтому «Valid» здесь означает
«сервер подтвердил существование», а не «человек читает эту почту».

## Тесты

```
python -m pytest -m "not slow"
python -m pytest
```

Первый круг быстрый (около полутора минут), второй полный (около семи).
Разделение сделано по замеру, а не по догадке; медленные файлы помечены
`pytestmark = pytest.mark.slow`.

Гейты проектов лежат в `.unlazy/*/GATES.md`, критерии проверки — в
[docs/КРИТЕРИИ.md](docs/КРИТЕРИИ.md).

## Куда что сложено

| Каталог | Что внутри |
|---|---|
| `core/` | движок: SMTP-диалог, DNS, прокси, скоринг, обогащение, парсер дорков |
| `ui/` | оба окна: `webapp.py` + `web/` (основное), `gui.py` + `panels.py` (запасное) |
| `api/` | локальный HTTP-API |
| `tools/` | вспомогательные скрипты (запуск гейтов, калибровка скоринга) |
| `tests/` | набор проверок |
| `docs/` | список всех критериев проверки |
| `data/` | кэш вердиктов, журнал прогона, долгая память (создаётся сам) |
